# 网页流程探测与 XPath 提取

## 触发与职责

- **仅显式触发**：用户明确要求网页操作流程探测、XPath 提取或验证时执行；普通网页开发不自动触发。
- 只交付**操作步骤、XPath、页面状态与验证证据文档**，供后续影刀开发参考；不编写或修改 RPA 代码，不运行影刀或部署。
- 以用户提供的业务目标、已确认的页面路径和当前环境为边界。可复用已有探测结果，但未经当前页面核实的选择器不能标为本次实测通过。

## 探测流程

1. **确认起点**：明确目标网页、入口、登录状态、操作范围、必要输入及预期完成状态。沿用已确认事项；影响业务结果或副作用的缺口先向用户确认。使用当前环境已授权的浏览器操作能力。
2. **识别页面状态**：确认目标元素位于主文档、iframe、弹窗还是新标签页；注意加载、遮挡、禁用状态及动态刷新。只检查当前步骤真正涉及的结构。
3. **提取并检查定位**：依据当前真实 DOM 提取 XPath，记录作用范围和命中数量；单目标必须唯一，多目标须符合预期范围。操作前检查目标语义及所需可操作状态（如可见、未被遮挡、可编辑或未禁用）；定位原则见下方正式文档。
4. **逐步实际操作**：在用户授权范围内允许所有交互类型，包括点击、输入、提交、下载等，示例不是白名单。按业务顺序执行并记录必要输入；已有授权不重复询问，授权不明的步骤先确认。
5. **验证闭环**：按该步等待条件观察操作后的实际状态，对照成功判据留存证据；XPath 命中或动作调用成功都不能单独证明流程成功。可能重复提交的动作不为验证而重做；结果不明时先核实状态，不盲目重试。
6. **处理阻塞**：唯一性、可操作性或操作后状态不符合预期时，记录失败证据并暂停依赖该结果的步骤；页面变化时重新核实 DOM，不推断未观察到的结构或结果。

## XPath 与影刀边界

- 元素库复用、XPath 构造及相对查找原则统一见 [browser.md](../../../../xbot-api-docs/docs/browser.md)。已有元素库名称可作为线索，不能冒充已提取的 XPath；无法取得 XPath 时标明缺口。
- iframe 按外到内分别记录各层 iframe XPath 与框内目标 XPath，并在各自上下文核对匹配；调用契约见 [iframe2-extension.md](../../../../xbot-api-docs/docs/iframe2-extension.md)，不将跨文档路径拼成普通 XPath。
- 业务取数、异步导出任务绑定及动态元素处理按需查 [网页自动化实践](../rpa-practices/references/web.md)；提取交互 XPath 不等于选择 XPath 读取业务数据，不额外扩展取数任务。
- 浏览器探测通过不代表影刀运行通过；标明验证环境及影刀兼容性未验证的范围，不为补充兼容性结论运行 RPA。

## 交付格式

先简述目标、起止状态和验证环境，再用简短步骤表交付；不倾倒整段 DOM。表中为格式示意：

| 步骤 | 前置状态、操作与输入 | XPath / 作用范围 | 等待与成功判据 | 结果与证据 |
| --- | --- | --- | --- | --- |
| 序号 | 当前状态 → 动作（必要输入） | 实测 XPath；页面 / iframe / 相对根节点 | 等待条件；预期完成状态 | 状态；命中数、可操作性、操作后观察及证据引用 |

- 证据使用必要的 DOM 摘要、截图引用、响应摘要或下载结果引用，注明对应步骤并脱敏；明确区分预期与实际观察，不记录凭据或敏感业务原文。
- **结果状态**：`已实测`（唯一性或多目标范围、可操作性及动作后状态均通过）、`仅定位`（已核实 XPath，未执行动作）、`待验证`（尚未完成检查，注明阻塞）、`失败`（检查或动作结果不符合预期）。静态材料不能冒充真实页面实测。
- 仅补充影响复用的页面差异、未覆盖分支及阻塞；不将单次探测推断为所有页面或店铺通用。

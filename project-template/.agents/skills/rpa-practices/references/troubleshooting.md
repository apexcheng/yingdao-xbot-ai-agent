# 影刀编码版通用排错

本文用于 API 页面的局部排错仍无法解决、问题跨越数据、xbot、浏览器、Excel / WPS 或市场指令时。

## 按需收集错误证据

先根据当前错误定位原因；证据不足时再针对性收集：

- 对应异常和必要的 `traceback.format_exc()` 堆栈、失败步骤与相关输入 / 返回。
- 涉及版本或环境时，检查对应影刀、浏览器、WPS 或市场指令版本。
- 涉及接口时，保留 request id 等能追踪失败的信息。

不要用“失败了”或截断截图替代已有完整证据；敏感信息须脱敏。

## 先判断问题层级

| 层级 | 优先检查 |
|---|---|
| 业务输入 | 空值、字段名、Sheet 名、日期和文本类型、重复数据、真实文件路径 |
| xbot API | 对象来源、函数签名、参数名与类型、返回值层级、是否误用相似 Python 库 |
| 环境 | 登录状态、验证码或风控、iframe、页面结构、文件占用、Excel / WPS 进程、Windows 窗口状态 |
| 市场指令 / 接口 | 扩展版本、可视化与编码参数映射、请求体层级、限流、500 和返回结构 |
| Agent 上下文 | 是否修改了错误目录、是否读取 AGENTS、是否使用过期文档、是否把推测当成事实 |

简单且根因明确的问题可直接修复；原因不明确时再验证具体假设，必要时构造最小复现，避免同时修改多个无关因素。

如果排错过程中改动已经扩大成明显的结构重写或大规模重构，但问题仍未解决，优先回到原始业务结构重新做最小修改；不要继续在未经验证的大改造上叠加补丁。

## 领域检查

### 浏览器

遇到 XPath 查到却无法点击、Code 106 或页面行为异常时，结合当前 URL / 登录状态、iframe、遮罩与 SPA 重绘判断原因。元素可能因重绘失效，必要时重新定位；不要仅凭错误码认定广告遮挡或一味增加超时。保留异常 Page 供排查只在当前任务需要时执行。

网页加载等待及具体 API 见 [browser.md](../../../../../xbot-api-docs/docs/browser.md)，跨 iframe 见 [iframe2-extension.md](../../../../../xbot-api-docs/docs/iframe2-extension.md)，异步任务表元素失效见 [异步导出](async-export-task-binding.md)。

### Excel / WPS

按当前故障确认文件 / Sheet / 区域、文件占用、驱动和保存结果。注意长数字精度和以 `=` 开头的文本可能被当作公式。下载文件的 `openpyxl` 后端可能不支持 `close()`，部分平台 XLSX 样式不一定能被严格解析；宽日期表头有读取异常时可分段核对列数。

WPS 打开示例见 [多数据源报表](multi-source-report-safety.md)，具体 API 和驱动差异见 [excel.md](../../../../../xbot-api-docs/docs/excel.md)。

### 市场指令与第三方接口

1. 从 [市场指令索引](../../../../../xbot-api-docs/docs/extension-instructions.md) 进入对应正式事实页，按知识库核对公开入口和签名；报缺少模块或入口时先检查、更新或重新安装指令。
2. 对比成功与失败请求的最小差异，不根据界面中文选项猜内部枚举。
3. `HTTP 500`、`unknownError` 或空返回都是失败证据，除非当前 API 契约明确说明，不得当成“没有数据”继续破坏性写入。
4. 保留原始错误和 request id；不提交扩展内部源码、账号或令牌。

## 验证结论

修复后只说明实际做过的验证。语法检查、单元测试、同步影刀和影刀编辑器内运行是不同的证据等级。

# 影刀专项日志查证与现场交付

只在用户明确要求调查某次 RPA 运行的日志或故障时使用。不适用于晨检、日报或日常巡检，不改变它们的检查、交付或录屏规则。

## 先核对运行，再解释故障

1. 用实际运行机的任务历史和日志确认：机器（主机名或约定标识）、RPA 名称、运行日期或任务 ID、实际加载的应用版本或源码，以及涉及的 Sheet、业务环节或店铺。不能用开发机当前源码代替运行时版本；核验不到时明确说明。
2. 用运行机实际日志的北京时间标注关键事件：`YYYY-MM-DD HH:mm:ss`，日志有毫秒时保留。范围已说明同一天时可以简写 `HH:mm:ss`。仅有视频偏移或缺少时钟时说明缺口，不把视频进度当实际时间。
3. 按同一业务对象写「最后确认成功的动作 → 失败的具体动作和目标 → 实际后果」。描述所见，不把等待、查找、点击、下载和写入当成同一个动作。区分已确认事实、合理推测和待查事项。引用日志文件或任务 ID、时间与必要行；默认不倾倒原始日志、堆栈或敏感内容。
4. 同一对象、同一原因的重试合并汇报，列出每次实际时钟时间及最终结果。后来运行成功不自动证明原对象已恢复；只有同对象的证据才能确认恢复。

示例（均为虚构）：

- `02:51:03.123` 已打开报表页 → `02:51:08.456` 未找到「开始日期」控件 → 没有点击日期控件，本店的「宝贝销售」Sheet 没有更新。日志未说明控件为何缺失。
- `09:15:20` 已点击「获取验证码」→ `09:17:20` 等待目标验证码满 2 分钟超时 → 本次登录未完成；随后在 `09:23:42` 同店重试并登录成功。

## 原始现场录屏

- 核对录屏与日志是同一运行机、同一任务或已核准的时间段，并包含所查动作。只交付已录制完成、关闭并核实可读的相关原始 MP4；不使用仍写入的文件、近似或其他运行的录屏冒充证据。
- 仅在适用本专项且复制获授权时，把符合条件、可以在指定范围共享的原始 MP4 复制到用户指定的内部中转目录；目录从私有或本地配置读取，不在公开仓库保存。复制后核对目标可读和文件大小一致，再报告完整文件路径。没有同一运行的已完结影片、没有安全的共享范围、缺少目录配置或未获授权时，明确说明没有交付录屏，不默认复制一批文件或发送原始日志。

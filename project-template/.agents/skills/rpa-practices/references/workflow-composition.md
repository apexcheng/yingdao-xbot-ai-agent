# 业务流程组合实践

本页说明多个已验证的技术能力如何协作完成一条真实业务流程，**重点是调用顺序、数据流、模块边界和失败取舍**；不重复维护 Web、WPS、日志和通知的 API 或专项细节。开发其它业务时借鉴组合方式，不照搬这里的业务字段、状态或保存政策。

## 真实案例还原度审查

- 对照案例引用的固定源码版本及已确认业务决策，分别检查**源码忠实度**（描述是否准确、有无夸大）和**流程可重建性**（能否理解并正确组合关键步骤）；篇幅长短不代表还原度。
- 重点核对主流程顺序、模块职责、数据交接、状态推进、失败与保存边界；缺少会让 Agent 实现出不同流程的条件时，补充必要说明和源码入口。
- XPath、具体店铺、固定字段坐标等局部实现保留在可追溯源码中，不为完整复刻而复制整套代码，也不把个别项目的业务取舍升级为通用规则。

## 表格更新

### 真实来源与适用场景

- 来源：影刀编码版「【表格更新】跨镜补货表」；[GitHub 固定版本 3a78997](https://github.com/apexcheng/cross-border-replenishment-rpa/tree/3a7899764960435767553f9cf00076adb5f19f74)（2026-10）。
- 该业务程序已在其它机器执行（用户确认）；本页以固定提交中的源码为准，不复制整个项目，也不据此声称该提交已单独做过实机验收。该提交的 17 项模拟测试已通过。
- 适用：从多个 Web / ERP 下载数据，更新同一个 Excel / WPS 工作簿的多个 Sheet，并在结束后记录结果、归档日志、发送钉钉通知。

### 一轮业务怎么串起来

```text
开始
  → 选择 Chrome Profile，有历史 Page 时关闭其中除最后一个外的页面
  → 强制结束旧 WPS 进程，打开一次目标工作簿
  → 读取工作簿中的上次成功时间、各国销量数据截止日期
  → 按业务顺序处理需要更新的任务：
       雅仓库存                 → 下载 → RAW 覆盖
       Shopee 官方仓库存        → 两地区导出 → 合并写入 RAW
       妙手 ERP 发货明细        → 下载 → RAW 覆盖；保留本轮源文件路径
       C-ERP 产品库             → 下载 → RAW 覆盖；保留本轮源文件路径
       Shopee SKU 映射          → 两地区导出 → 合并写入 RAW
       三国销量                 → 复用 / 补下源文件 → 商品规格同步
                                → 计算日期销量 → 逐国写入
  → 尝试保存同一目标工作簿 → 无目标工作簿或保存成功时才关闭 WPS
  → 保存成功且有至少一项处理成功时，生成最终工作簿快照
  → 钉钉发送本轮业务结果
  → 汇总包含通知结果的中文业务日志 → 导出运行日志
```

这里是 **6 个处理入口、8 个受跟踪 Sheet**（三国分别记录结果）。任务集固定，主流程直接顺序调用，不为了复用异常处理而改成配置列表 + 循环；地区和国家在同一处理规则下需要遍历时使用循环。

**跨模块传递的是实际需要的数据，不是万能上下文字典。** 主流程持有一个目标 `workbook`；来源模块只有完整执行 `update()` 并返回后，主流程才拿到妙手 / C-ERP 的文件路径。本轮缺少路径时，国家销量模块仅调用相应 `download()` 重新下载并打开源文件，**不会补做此前失败或跳过的 RAW 更新，也不改写它原来的结果**；不引入跨轮文件缓存。国家模块先取得 / 打开 C-ERP，再取得 / 打开妙手，之后同步商品规格、计算销量。来源工作簿由业务模块打开，目标工作簿最终由主流程统一保存。

### 可仿照的模块接口与重试边界

```text
run.main()
  ├─ workbook = open_workbook(目标文件)                 # 一轮一个共享目标
  ├─ update_xxx.update(workbook, run_logger)
  │    ├─ filepath = download_with_retry(download, ...) # 只重试整个下载函数
  │    ├─ source = open_workbook(filepath)               # Excel 和 CSV 均用 WPS
  │    └─ replace_raw_area(workbook, ..., source, ...)    # 只更新约定 RAW 区
  └─ update_country_sales.update(workbook, cerp_filepath, miaoshou_filepath, ..., set_state)
```

- **Web → WPS 的契约是本轮下载的文件路径**，不是共享 Page 或把所有处理揉进一个浏览器函数。雅仓 / 妙手通过网页及已验证的市场指令完成登录、验证码和下载；Shopee 两个模块共享登录、切换地区、导出任务等待；C-ERP 市场指令初始化会话并返回 CSV 路径。
- **重试仅包裹 `download()`**，最多尝试 3 次（首次 + 最多 2 次重试）。Shopee 一次下载包含两个地区：第二地区失败后的下一次尝试从第一地区重新执行。源文件打开、RAW 写入、销量更新、工作簿保存和钉钉发送都不在这个统一重试范围内。
- **RAW 写入**：读取源首个 Sheet 的有效范围，只清空目标约定的 RAW 内容区域，读取源单元格并批量 `set_range`；多来源追加时跳过后续文件的表头。写入前对超长数字 ID 做文本保护，避免 Excel 精度损失。源文件和目标文件都通过 `xbot.excel.open(kind="wps", visible=True, update_links=False)` 打开；由公用函数激活并最大化。

### Web、数据、WPS 的连接点

1. **Web 获取**：雅仓、妙手和 Shopee 由各自模块处理页面；C-ERP 的页面生命周期由市场指令负责。需要网页登录时在登录页完成登录，**新建 Page** 再进入业务 URL，避免依赖登录后的不确定跳转。雅仓、妙手和 Shopee **下载成功后关闭业务 Page，下载阶段异常则保留尚未关闭的 Page**；之后若在 WPS 写入时报错，不能假定原下载 Page 还存在。通用页面加载与异常处理见 [Web 实践](web.md)。
2. **异步导出绑定**：各平台当前的身份判定强度不同，均不能等同于拥有可验证的本轮请求 ID：

   | 来源 | 本项目实际识别办法 | 边界 |
   | --- | --- | --- |
   | Shopee | 任务分类 + 文件名前缀 / 后缀 + 提交时间不早于本轮触发前 5 秒；候选必须唯一且成功，按文件名与提交时间重新定位下载 | 无时间上界，地区仅用于操作及日志，不参与候选筛选；**未使用导出前快照**，仍可能匹配同期其它请求 |
   | 雅仓 | 下载管理中匹配“库存导出”及当前小时的第一条记录 | 同一小时的历史任务可能被选中 |
   | 妙手 | 固定导出模板，记录点击时间后以 `*.xls*` 等待新下载文件 | 未按唯一任务 ID 或独有文件名绑定；同期其它下载可能干扰 |
   | C-ERP | 直接使用市场指令返回的 CSV 路径 | 市场指令内部导出身份识别未在本案例验证 |

   新项目优先参考 [Web 实践中的本轮导出绑定规则](web.md#绑定本轮导出任务)，而不是复制本项目的弱身份匹配。
3. **WPS 更新**：源文件和目标工作簿均使用 WPS 打开；目标工作簿只打开一次，各更新模块通过共享 `workbook` 写入指定 RAW 区。两地区文件合并时，仅首份保留表头，后续份跳过相应表头；国家销量按已有截止日期重算需要的日期，不覆盖其它业务区域。细节见 [Excel / WPS 实践](excel-wps.md)。
4. **计算与结果**：三国销量共用同一来源与计算结果，但**商品规格配置区先同步写入**，再共同聚合销量、预校验各国日期表头和 SKU 清单；全部准备好后才逐国写销量区域。日期表头按需分段读取，相邻日期列合并成矩阵批量写入。即使后来预校验失败，之前的规格配置修改仍可能在本轮被保存；预校验保护的是销量区域，不代表整份工作簿尚未修改。

### 国家销量日期与状态的真实规则

- 妙手下载的是**近 30 天下单时间范围**的订单原始数据；计算按有效订单状态、站点、销量日期、归一化规格汇总数量，通常取付款时间，个别平台有备用日期。固定导出模板的字段位置、规格匹配和冲突跳过策略属于此项目业务事实。
- 三国共用的**可更新截止**为 `min(来源有效日期最大值, 昨天)`，不能早于任何国家已有截止。实际写入的日期来自源数据中**真实出现的日期集合**，不是自动补齐每个自然日；三国共用的日期上限也不证明每个国家每天都有完整数据。
- 单国计算起点是 `min(该国已有截止, 可更新截止 - 1 天)`：即使已有截止等于可更新截止，也会把筛选下界退到前一天；**只有来源日期集合包含可更新截止当日，才会重算该日**。被选中的日期里没有对应 SKU 销量时写 0，没选中的日期列不写。如果表头存在“今天”列，另将今天列清零。各国成功后才推进截止日期；未匹配的规格销量按本项目业务规则跳过并记录。
- **工作簿持久状态 ≠ 本轮 `RunLogger.results`**：前五个独立任务仅根据工作簿上次成功日期为今天而跳过；三国必须同时满足“本轮未初始化截止配置、三国截止都为昨天、三国上次成功均为今天”才整体跳过。跳过只记本轮结果，不回写状态区。
- `_set_state()` 在工作簿中按顺序写检查时间、结果、说明、成功时间、国家截止日期，与业务数据一起等最后一次 `save()`。这些单元格写入**不是事务**；状态写入失败也可能中断整轮，而不是保证后续独立任务始终执行。截止日期虽最后写，也不代表此前状态完全没变。

### 已确认的保存和失败边界

- **独立任务**：业务模块失败且成功写入失败状态时，记录该 Sheet 失败后仍允许执行其它独立任务；状态回写本身失败等未被局部捕获的异常会中断整轮。今天已成功的任务可按本项目上次成功时间规则跳过。
- **依赖任务**：三国共用来源和预计算；共同准备失败影响三国。逐国写入时，前一国失败则当前国家记失败、后续国家记“未执行”，已经处理完成的国家仍保留结果。
- **保存策略（本项目明确允许）**：即使部分更新失败，**也允许在本轮结束时保存已写入的工作簿内容**，包括发生异常前的部分写入；不自动回滚，不把这个选择推广为所有项目的默认策略。RAW 清空后若读取 / 写入失败，也可能把清空或部分写入保存，属于此项目已接受的业务取舍。
- **处理完成 ≠ 已保存**：各 Sheet 的成功记录先表示“处理完成、等待保存”；主流程 `workbook.save()` 成功后，运行结果中的 `saved` 才置为真。保存失败保留 WPS 现场，通知中不得称为“已保存”。
- **通知独立**：保存、快照、WPS 关闭或钉钉发送失败分别反映真实结果；不能因钉钉失败把已保存的业务结果改为失败。跨轮状态和通知的职责边界见 [跨轮次处理状态与重试](cross-run-state-and-retries.md)。
- **启动和脱敏的范围**：本项目启动时强制结束系统的 WPS 相关进程，可能丢失**其他 WPS 文档**未保存内容；这是特定运行环境的既有取舍，不是通用安全清理方式。日志脱敏仅做已配置凭证的精确文本替换，不能代替对其它业务敏感信息的检查。

### 日志、通知与复用原则

- 运行日志采用 `【业务对象】操作：结果｜必要信息`，正常路径记录关键节点；最终失败保留一次完整堆栈。详见 [中文业务上下文日志](logging.md)。
- 状态区仅记录业务结果、处理时间和必要说明；日志文件与历史快照用相同的执行开始时间命名，不另外维护用于关联的业务字段。
- **快照是本轮成功保存后的最终副本，不是更新前备份**：仅工作簿已保存且有至少一个 Sheet 处理成功才生成，可能包含部分失败写入；全部跳过则不创建。钉钉显示的日志文件名是**计划随后导出的路径**；通知后才汇总整轮状态并导出日志，导出失败不重发通知；导出成功后打印的“日志导出完成”未必包含在这次导出的文件中。未配置 Webhook 明确记为跳过，不当作发送失败。
- 钉钉消息按 Sheet 展示更新、跳过、失败及未执行结果，并区分保存状态；不要把代码级流水日志复制到通知中。详见 [钉钉通知实践](dingtalk.md)。
- **借鉴组合，不复制业务**：可参考“多来源 → 各自下载处理 → 共用目标工作簿 → 统一保存 → 结果通知”的调用关系；不要复制 Shopee XPath、店铺 ID、验证码流程、国家销量字段位置、截止日期初始化值、重试次数、快照数量或具体的保存失败策略。
- **需要具体实现才打开源码**：优先从本页理解全局，再按上面的文件索引选读 1～2 个模块。新增或修改 API 时以 [正式 API 文档](../../../../../xbot-api-docs/docs/browser.md) 及相应知识页为准，不用历史项目反推 API 契约。

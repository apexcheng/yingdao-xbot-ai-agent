# 跨轮次幂等、处理状态与重试

适用：RPA 会定时或重复扫描同一业务对象，且需要避免重复执行、跨轮次继续处理或汇总历史处理结果时。单次运行、天然只读、重复操作无影响的任务，不为将来可能需要而新增 SQLite、状态表或重试框架。

## 先确定「同一件事」的身份

- **按业务动作的唯一性选键**，不要单靠执行时间或本轮页码。参考库存监控：`平台 + 店铺 + 消息时间 + 商品 ID + SKU 身份`，区分不同店铺、消息和规格；其它业务应按自身真实唯一性选择订单号、商品 / SKU、批次或其它必要字段。
- 实际需要持久化时，在已有存储中对身份键建立唯一约束，重复发现就取原记录并检查状态；不因为扫描到第二次就自动创建第二条任务。参考 [库存监控快照](../../../../../reference-projects/inventory-monitor/README.md) 的 `snapshot/database.py:get_or_create_alert()`。
- 不假定「同一商品」必然是同一任务，也不为不需要去重的业务额外发明全局任务 ID 或历史快照。

## 状态区分「是否可继续」，次数记录「已经尝试了多少」

下表是**参考项目使用的语义示例，不是所有项目的统一枚举**：

| 状态示例 | 含义 | 下一轮 |
| --- | --- | --- |
| `pending` | 已发现，还没有确认处理完成 | 如业务要求，继续处理 |
| `failed` | 本次未成功，且问题可能恢复 | 未达项目设定的次数上限时重试 |
| `success` | 实际业务结果已核实成功 | 不重复执行 |
| `skipped` | 按业务条件明确不需要本次操作 | 仅在「跳过就是终态」时不再执行 |
| `failed_final` | 明确无法自动修复，或重试已到上限 | 停止自动重试，保留原因供人工处理 |

- **是否重试**由当前状态、业务错误性质和已有尝试次数共同决定。技术性暂时失败可以按业务要求重试；身份映射缺失、数据明确不合法等不能靠重复点击解决的错误，应标记不可自动重试或交给人工处理。
- 只有确实执行了一次业务尝试，才按项目口径增加尝试次数；达到上限后停止自动尝试。不要仅因重新扫描、打开页面或查询记录就增加次数。
- 示例中的 `failed_final`、`skipped` 等名称及具体上限属于来源项目，不要复制成每个影刀项目的强制字段或固定重试次数。

## 执行与落盘顺序

1. 从本轮真实数据识别业务对象，读取已有记录；满足终态规则的对象直接跳过。
2. 确认需要操作且仍可重试后执行业务动作。提交类动作尽量根据系统实际结果复核，而不是只凭点击成功。
3. 把**处理结果、状态、已尝试次数、必要结果/失败原因、更新时间**写回同一业务记录；下一轮应以这份持久化事实判断，而不是以本轮内存变量判断。参考 `snapshot/database.py:save_alert_result()` 与 `snapshot/pdd.py:process_shop()`。
4. 单个对象失败是否继续处理其它对象，取决于当前业务依赖；独立任务不必因为一项暂时失败而全部中断。

**异常退出的关键边界：**如果外部提交已经成功，但程序尚未来得及保存结果，数据库仍可能显示待处理；数据库唯一键只能避免重复登记，**不能保证外部操作恰好执行一次**。对重复提交有副作用的任务，恢复后应先核对真实业务结果，再决定是否重新执行；不要把「记录不存在 / 状态未成功」一律当成安全重试依据。是否需要更复杂的恢复协议由真实业务决定，不为防御未来而默认增加。

## 跨轮次扫描与通知

- 如果历史未完成项不一定在最新消息第一页，下一轮按存储中的「仍需处理项」确认是否继续查找；扫描何时停止按实际列表结构与业务条件决定。未找到的项目仍需区分「暂未找到」与「已最终失败」，不能因为本轮没看到就擅自标成完成。
- **业务状态、发送通知结果是两件事。**业务操作完成后通知失败，不应把成功操作改成失败并再次执行；需要保证通知可再次送达时，单独保存必要的通知进度。参考 `snapshot/run.py` 的汇总窗口与 `snapshot/dingtalk.py` 的通知返回。
- 历史数据保留多久、按何种时间清理，以及是否使用 SQLite、既有数据库还是工作簿状态区，都按当前业务的数据量、查询和持久化需求决定；不要为所有项目预设保留天数或新建存储。

## 参考边界

上述判断来自 [库存监控冻结源码](../../../../../reference-projects/inventory-monitor/README.md)（2026-09-14）。它证明一种实际落地方式，不证明所有项目必须采用其表结构、状态枚举、重试次数、分页终止条件、库存业务口径或当时的页面操作写法。一般的 Excel 保存策略另见 [多数据源报表安全边界](multi-source-report-safety.md)，两者不应混为一谈。

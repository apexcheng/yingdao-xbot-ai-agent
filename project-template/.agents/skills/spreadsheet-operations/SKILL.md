# 表格操作（影刀 WPS）

本 Skill 只约束交付的影刀 RPA 运行时表格处理代码。Agent 直接检查、修改、计算或保存表格文件（包括项目模板和运行产物）时，按自身执行环境的适用规则选择工具，不受本 Skill 的 `xbot.excel` / WPS 要求限制。API 参数和返回值查 [xbot.excel 正式文档](../../../../xbot-api-docs/docs/excel.md)；业务模块命名与函数边界见 [编程风格](../code-quality/references/coding-style.md)。不重复加载其它表格操作规范。

Agent 直接修改已有工作簿时，默认保留文件原有计算模式及相关计算标志，按自身工具规范检查目标文件占用和验收；仅在用户明确要求时修改计算设置。不得套用 RPA 运行时设置，擅自切换共享 WPS 实例的计算模式。

新开发的 Excel / CSV 处理代码默认采用 `xbot.excel` / WPS；维护已有项目时遵循该项目已确认的技术方案，不因局部修改而自动替换，确需变更先说明影响并取得确认。下列 WPS 操作规则适用于采用 WPS 的流程。

测试时，用户明确指定专用测试工作簿就直接使用，不强制复制；若要求保留 WPS 打开且不保存，则按要求跳过测试收尾的保存与关闭。生产运行仍遵守下述规则。

## 打开与使用工作簿

1. 本轮程序第一次打开 WPS 前，直接调用 `xbot.excel.kill_excel_process("wps", True)` 结束残留进程；不判断其他 WPS 文件是否正在编辑。本轮已经打开目标工作簿后，不在打开源文件前再次结束 WPS。
2. 普通打开流程使用 `workbook = xbot.excel.open(file_name=str(target), kind="wps", visible=True, update_links=False)`。采用 WPS 打开 Excel / CSV 时保持窗口可见。
3. **经营报表 RAW 更新 RPA 在打开目标工作簿前必须切换为手动计算。** 先创建可见空白工作簿，再在同一 WPS 实例内设置手动计算及保存前不自动重算，随后打开目标工作簿。其他 RPA 是否采用手动计算，按项目已确认需求决定。调用方式见 [WPS 打开前切换为手动计算](../../../../xbot-api-docs/docs/excel.md#wps-打开前切换为手动计算)。
   - 计算模式作用于整个 WPS 实例。创建空白工作簿后，无论是否已有其他工作簿，均设置手动计算并继续；不得以其他工作簿存在为由增加前置检查、跳过设置或停止运行。打开前后检查手动模式是否生效，实际设置失败按技术异常处理；临时空白工作簿用完后关闭且不保存。
   - 手动计算下保存的文件可能仍带有上次计算的结果。经营报表 RAW 更新不主动重算、不为刷新公式值切回自动计算；业务计算由工作簿自身完成，运营手动更新不依赖 RPA。其他确需读取最新公式值的流程，遵循项目已确认的取值时序，不将重算作为 RAW 更新的通用步骤。
4. 每次打开工作簿后，立即激活并最大化：

   ```python
   workbook.workbook.Activate()
   workbook.workbook.Application.WindowState = -4137
   ```

5. 根据任务选择读取和写入接口；批量搬运数据可使用 `get_range()` 读取、整理后用 `set_range()` 写入。已有二维数据直接写入，不创建临时工作簿中转。
   覆盖旧数据时只清空当前业务约定的数据区域，不整表 `clear()` 影响公式和格式。其他确需读取公式值的流程，以表格软件实际计算结果为准，不由 RPA 复刻业务计算。
   写入 RAW 时，表头和字段值中以 `=` 开头的业务文本，按 [WPS 批量写入文本保护](../../../../xbot-api-docs/docs/excel.md#113-wps-批量写入以--开头的文本) 处理；真正需要执行的公式不得转义。
6. 对已确认由工作簿公式完成业务计算的项目，RPA 负责模拟操作和搬运 RAW / 事实数据。除用户明确要求外，不自行增加源文件与目标 Sheet 的表头一致性校验，不判断数据是否符合业务预期，不因空文件或只有表头拒绝覆盖。RPA 不复刻工作簿公式或承担业务计算；经营报表 RAW 更新不主动重算或核对工作簿公式。
   **RAW 搬运按每份文件的约定范围完整读取。多份文件按顺序拼接，每份的表头和范围内的说明行一起写入。覆盖从约定起点写，追加从目标 RAW 区最后一行的下一行写，区域为空就从约定起点写。**
   - 覆盖示例：清空约定的旧 RAW 区，从约定起点写入 `A 表头 → A 数据 → B 表头 → B 数据`。
   - 追加示例：目标 RAW 已占第 1～10 行，从第 11 行写入 A 表头，接着写 A 数据、B 表头、B 数据。只有表头的文件也保留这一行。

   空结果同样按约定清理旧 RAW，保留明确要求的标识字段文本保护。取得下载路径后直接按业务流程读取，不额外验证文件存在性。
   操作所需的任务绑定、状态等待和下载等待仍正常执行，技术异常如实抛出，不将读取失败当成空数据。
7. 多个步骤需要同一工作簿时复用已打开的对象，避免无必要重复打开；函数的输入与返回值按实际职责确定。

## 多 Sheet 更新与收尾

1. 主流程直接写明下载、打开、写入、保存和关闭的先后顺序。目标工作簿一轮只打开一次，各业务模块接收该对象。
2. **每个 Sheet 的完整更新流程最多尝试 2 次**（首次执行 + 失败后重试 1 次），包括下载、读取和写入，不仅重试下载；不把整轮保存和通知纳入该重试。A Sheet 最终失败时记录错误，继续更新独立的 C Sheet；存在前置依赖的 Sheet 按当前业务确认的依赖关系及失败策略处理。各 Sheet 处理完后统一 `workbook.save()` 一次，不在每个 Sheet 更新后保存。
3. 下载函数按实际流程返回文件路径、已打开的工作簿或所需数据；避免无必要重复下载或打开。
4. 完成本轮处理后，**先保存目标工作簿，再统一关闭全部 WPS 表格**，不额外维护逐工作簿关闭清单。异常时按原业务异常处理未保存内容；清理失败不能覆盖原来的业务异常。
5. 按已确认的项目架构和实际职责组织下载、更新及必要的结果读取代码；多个业务确实复用相同且完整的技术操作时才提取公共函数。

不为了潜在需求新增跨轮下载缓存、重复状态源、补跑开关、历史兼容和复杂恢复分支。

# 表格操作（影刀 WPS）

开发影刀表格更新程序时遵守本页。**本页只规定业务程序运行时的表格操作，不要求 Agent 在开发期检查工作簿结构、公式或数据时启动 WPS、导入 `xbot`。**API 参数和返回值查 [xbot.excel 正式文档](../../../../xbot-api-docs/docs/excel.md)；业务模块命名与函数边界见 [编程风格](../code-quality/references/coding-style.md)。不重复加载其它表格操作规范。

测试时，用户明确指定专用测试工作簿就直接使用，不强制复制；若要求保留 WPS 打开且不保存，则按要求跳过测试收尾的保存与关闭。生产运行仍遵守下述规则。

## 打开与使用工作簿

1. 本轮程序第一次打开 WPS 前，直接调用 `xbot.excel.kill_excel_process("wps", True)` 结束残留进程；不判断其他 WPS 文件是否正在编辑。本轮已经打开目标工作簿后，不在打开源文件前再次结束 WPS。
2. **业务程序运行时**，所有表格文件，包括 Excel 和 CSV，都使用 `xbot.excel.open()` 的 WPS 驱动打开，不改用 `openpyxl`、`pandas` 或其它方式加载；该限制不适用于 Agent 的开发期文件检查。
3. 统一使用 `workbook = xbot.excel.open(file_name=str(target), kind="wps", visible=True, update_links=False)`；不使用 `visible=False`。
4. 每次打开工作簿后，立即激活并最大化：

   ```python
   workbook.workbook.Activate()
   workbook.workbook.Application.WindowState = -4137
   ```

5. 每个 Sheet 的数据源更新使用 `get_range()` 读取 → 按约定整理数据 → `set_range()` 写入。已有二维数据直接 `set_range()`，不创建临时工作簿中转。
   覆盖旧数据时只清空当前业务约定的数据区域，不整表 `clear()` 影响公式和格式。写入原始数据后确实要立即使用公式计算结果时，按实际 WPS 计算结果处理，不能用 Python 模拟计算代替。
   写入 RAW 时，表头和字段值中以 `=` 开头的业务文本，按 [WPS 批量写入文本保护](../../../../xbot-api-docs/docs/excel.md#113-wps-批量写入以--开头的文本) 处理；真正需要执行的公式不得转义。
6. **RPA 负责模拟操作和搬运 RAW / 事实数据，工作簿公式负责业务计算。** 除用户明确要求外，不自行增加源文件与目标 Sheet 的表头一致性校验，不判断数据是否符合业务预期，不因空文件或只有表头拒绝覆盖，也不复刻、重算或核对工作簿公式。
   按约定区域使用 `get_range()` 读取、`clear_range()` 清理并用 `set_range()` 写入；空结果同样按约定清理旧 RAW，保留明确要求的标识字段文本保护。取得下载路径后直接按业务流程读取，不额外验证文件存在性。
   操作所需的任务绑定、状态等待和下载等待仍正常执行，技术异常如实抛出，不将读取失败当成空数据。
7. 表格处理函数直接接收已经打开的 `workbook`；禁止 `load_excel_matrix` 及同类再次加载工作簿的封装。多个函数需要同一对象时由主流程局部变量持有、传递。

## 多 Sheet 更新与收尾

1. 主流程直接写明下载、打开、写入、计算、保存和关闭的先后顺序。目标工作簿一轮只打开一次，各业务模块接收该对象。
2. **每个 Sheet 的完整更新流程最多尝试 2 次**（首次执行 + 失败后重试 1 次），包括下载、读取和写入，不仅重试下载；不把整轮保存和通知纳入该重试。A Sheet 最终失败时记录错误，继续更新独立的 C Sheet；存在前置依赖的 Sheet 按当前业务确认的依赖关系及失败策略处理。各 Sheet 处理完后统一 `workbook.save()` 一次，不在每个 Sheet 更新后保存。
3. 下载函数供后续步骤直接处理表格时，返回已经打开的源 `workbook`，由主流程持有并传递；如果另一个业务需要复用前一个业务下载的文件，则前一个业务返回 `filepath`，后一个业务接收该路径。不重复下载或重新加载已打开的工作簿。
4. 完成本轮处理后，**先保存目标工作簿，再统一关闭全部 WPS 表格**，不额外维护逐工作簿关闭清单。异常时按原业务异常处理未保存内容；清理失败不能覆盖原来的业务异常。
5. 表格更新业务各自放在 `update_xxx.py` 中，例如 `update_erp_date.py` 和 `update_sales.py`。同一业务的下载和更新放在一起，不因读取 C-ERP 数据就把其它业务的函数放入 C-ERP 模块；多个业务确实复用相同且完整的技术操作时才提取公共函数。

不为了潜在需求新增跨轮下载缓存、重复状态源、补跑开关、历史兼容和复杂恢复分支。

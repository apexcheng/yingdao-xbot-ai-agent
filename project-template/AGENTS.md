# AGENTS.md

本文件用于真实影刀 xbot / 编码版项目，只保留执行任务时必须常驻的约束。详细示例和 API 事实仍以用户提供的知识库为准，不在项目内复制第二套文档。

## 需求理解与合理性判断

1. **Agent 决定怎么实现，用户决定程序应该做什么。** 先查用户已确认的要求、当前项目规范和成熟实现；能自行核实的事实自行查明，不要求用户提供。规则明确、目标清楚时直接采用最小正确实现，变量命名、简单循环等普通实现细节不重复请示。
2. 查明现有规则后，如果仍有不同选择会改变业务结果、数据口径、数据完整性、失败后的停止 / 跳过 / 继续、风险承担或长期规则，或同一业务术语含义冲突，**先集中询问真正需要用户决定的分歧**，说明影响并推荐最简单方案，确认后再实现相关行为；不以“健壮性”或通用最佳实践替用户决定。
3. 当前需求和已有规则不需要的抽象层、配置、缓存、状态管理、兼容逻辑等直接不做；确有必要且会明显扩大实现范围时，先说明必要性并取得用户确认。防御性措施按下方「代码实现」中的可选防御规则执行，不为低风险细节增加提问。
4. 如果发现只有为兼容旧值增加映射或其他兼容代码才能继续，必须先暂停相关实现并告知用户存在阻塞，说明冲突和影响；未经用户明确确认，不得自行添加兼容代码。

## 开始任务

1. 业务规则优先级：**用户明确确认的业务目标、范围、验收标准和取舍决定 > 当前项目正式 PRD / 规范 > 当前代码与既有业务约定 > 历史经验**。用户明确确认的业务决策与 PRD / 规范冲突时，以用户当前决定为准；若该决定改变长期业务规则，应同步更新对应正式文档。
2. 用户明确确认的业务规则、字段名、路径、Sheet 名等项目专有事实视为已确认输入。优先参考当前项目已有的同类实现。需要一致性检查、非简单改动的进一步简化，或用户要求代码审查时，按任务目的使用 `.agents/skills/code-quality/SKILL.md` 对应部分；只读审查不得自动修改文件。
3. 知识库固定路径为 `C:\Users\Administrator\Desktop\影刀xAI开发指南`。需要检索影刀知识时按下方“xbot 与知识库”的顺序查询；目录不可用时说明缺口，仅暂停依赖该知识的改动，其他明确任务继续执行。

## 项目分析与执行边界

ShadowBot CLI 只用于影刀自身运行和生命周期操作。除非用户明确指定，否则不得启动影刀主程序。

## 代码实现

1. 自动化默认保持自上而下、业务顺序可见；固定任务直接依次执行。`run.py` 保留影刀 Code 流入口 `main(args)`。仅实现当前确定需要的行为，不为未来假设增加抽象或选项。
2. Python 模块的 `import` / `from ... import ...` 统一放在文件顶层，不在函数、分支或异常处理中延迟导入，使依赖缺失能在应用或模块加载时暴露。
3. 数据获取层返回实际结果并传播技术异常；空值、重复结果以及失败后停止、跳过或继续，由当前业务规则决定，不在底层代为选择。
4. **未经确认不新增可选防御。** 按已确认的业务流程与 API 契约完成必要检查，保留既有保护并让失败如实传播；额外前置校验、重试、回退、兜底、预检、重复读取和状态管理等，若改变业务行为或扩大范围，应先询问。典型反例：对写入侧已保证唯一的数据，在读取 / 回填侧再建去重或 visited 集合——这类记忆状态属于未确认的可选防御，不得默认添加。未要求的可选防御直接不做，仅报告影响本次验收的已知限制。

**编码标准按需读取：** 需要决定单 Page 函数边界、变量 / XPath、配置传递、异常收尾或日志封装时，读取 `.agents/skills/code-quality/references/coding-style.md` 的对应节；代码审查也以该文件为编码标准。普通明确小改不必加载全文。

## xbot 与知识库

1. Agent 不知道影刀代码怎么写或需要查询 API / 市场指令用法时，**先查 Skill 和知识库**；只有其中没有所需内容，才查源码。禁止跳过知识库直接查源码，也不根据通用 Python 经验或旧项目记忆猜 API。已有项目代码不能推翻正式 API 事实。
2. 通过知识库 `llms.txt` 或 QMD 定位相关 Skill 和正式文档；搜索摘要不能替代正式正文。
3. 市场指令使用 `from ... import ...` 导入公开方法并调用，**禁止在当前项目复制或重写市场指令源码，也禁止直接修改项目安装的市场指令包（`xbot_extensions`）中的代码、资源与元数据**。这些包是影刀市场指令的安装副本，更新市场指令会覆盖本地修改。功能修正应在当前项目业务代码中处理，或在市场指令源项目修复并发布更新。项目未安装时只提示安装、更新对应市场指令，不自行复现。调用任何市场指令（`xbot_extensions`）时，在调用点紧邻添加功能和参数含义注释；含义以正式事实页为准，不猜测。
4. 网页业务默认使用 `xbot.web`；所有 Page 新建、跳转、刷新等加载完成后，先 `page.wait_load_completed(...)`，再统一 `time.sleep(2)`，然后开始业务操作，避免 JS 仍在初始化。需要等待异步业务结果时仍须检查实际状态，不用不断叠加固定等待。
   程序开始运行时先获取所有浏览器 Page，只关闭 `all_page[:-1]`，保留最后一个 Page，避免 Chrome 进程退出。业务执行到一半异常中断时，不关闭正在操作的 Page，方便排查。
   网页数据优先从网络响应获取，DOM / XPath 主要用于触发操作；用户提供数据提取 XPath 时不先探测网络响应，直接询问是否确认放弃网络响应、改用 XPath 提取，确认后再执行。详情见 `.agents/skills/rpa-practices/references/web.md`。
   仅在用户明确要求网页操作流程探测、XPath 提取或验证时使用 `.agents/skills/web-workflow-extraction/SKILL.md`，交付流程与 XPath 文档及证据；普通网页开发不自动触发。
5. 影刀日志使用 `from xbot.app import logging`；动态内容使用完整 f-string，异常堆栈使用 `traceback.format_exc()`。业务日志默认采用简洁的中文上下文格式，记录业务对象、动作和必要结果；示例见 `.agents/skills/rpa-practices/references/logging.md`。
6. **严格禁止 Agent 直接修改 `selectorsV2.xml`**：不得创建、编辑、格式化、覆盖或补丁修改该文件。需要增删或调整元素库时，Agent 只能提示用户自行通过影刀编辑器修改，不得代替用户修改文件；业务代码只读取并使用项目中已有的元素库名称。
7. 需要操作 ShadowBot CLI 时，按需读取 `.agents/skills/xbot-tools/SKILL.md`；命令参数以本机帮助为准。
8. 开发 Excel / CSV 表格更新程序时按需读取 `.agents/skills/spreadsheet-operations/SKILL.md`；跨轮次状态、Web 导出、多技术流程组合、钉钉通知及跨层排错，按需读取 `.agents/skills/rpa-practices/SKILL.md`，不默认加载全部材料。

## 验证与同步

1. 按风险做最小必要验证；默认不新增测试或运行无关全量检查。高风险写入前提示具体数据风险和可能影响，不默认设计回退方案。
2. 新增项目根目录 `.py` 文件时，文件名去扩展名后不得与 `package.json` 中已有 flow 的 `name` 重复，例如已有名为 `init` 的 Visual flow 时不能新建 `init.py`；撞名登记后 Studio 打开项目可能报“应用文件已损坏”，排查与修复见 `.agents/skills/xbot-tools/references/project-diagnostics.md`。
3. 用户说“部署”或“push 并部署”时，按 `.agents/skills/xbot-tools/SKILL.md` 直接单次调用 `scripts/deploy_app.py`，传入 Commit / 版本说明，自动完成 Git、必要的 Code flow 注册、Studio 同步、发布及线上版本核验，不重复手动拆步执行。
4. 用户单独说“push”时，Agent 正常执行 git commit 并 push 到 GitHub / Gitee 远程仓库，不部署影刀。执行前确认有改动需要提交，并使用清晰的 commit 信息。

## 安全与汇报

1. 不隐藏副作用，不通过吞异常、静默失败或模糊返回值让主流程看起来成功。

# 真实实现参考

`reference-projects/` 是**唯一的项目级实现案例库**，保存经过筛选、可追溯到固定 Git commit 的真实影刀项目案例。既可以保存脱敏源码快照，也可以仅编写完整流程说明并链接固定提交。用于了解真实项目怎样组织和落地，不把完整 Demo 分散在 Skill 内。

## 定位

- 这里不是项目模板。新建项目仍以 `project-template/` 为准。
- 这里不是开发规范。代码结构与开发行为仍以 `project-template/AGENTS.md`、项目 Skill 中的正式知识为准。
- 这里不是 API 文档。xbot API、市场指令参数和返回值仍以 `xbot-api-docs/` 为准。
- 案例保留历史实现事实，因此可能存在来源项目当时尚未清理的 TODO、历史兼容代码或后来已被知识库规则改进的写法。

## 什么时候读取

只有当前任务确实需要项目级实现参考时才读取，例如：

- 多平台、多店铺或多业务模块如何组织主流程。
- 持久化状态、幂等、重试和终态如何组合。
- 日志、业务结果通知和程序异常通知如何在真实项目中协作。
- 多个 xbot / 市场指令能力组合成完整自动化时，文件职责如何划分。

单个 API、单个 XPath、简单页面操作、单表处理等问题不需要读取真实实现参考，应直接查对应正式知识。

## 参考优先级

参考项目只能提供实现思路和真实案例，不能覆盖更高优先级事实。开发真实项目时仍按以下顺序判断：

1. 用户当前明确要求。
2. 当前项目正式 PRD / 规范和当前项目已确认业务事实。
3. 当前项目代码与已验证运行行为。
4. 知识库正式规则与 API 事实。
5. 真实实现参考。

如果参考项目与当前知识库规则或 API 文档冲突，以当前正式知识为准。

## 收录与更新

1. 每个参考项目必须说明来源项目、固定 Git commit、案例时间和适合参考的能力。
2. 需要复现本地源码结构时可保留脱敏快照；已有可访问的固定 Git commit 时，优先在案例 README 中引用源码，**不额外复制一份**。不得复制 `.dev/`、IDE 配置、数据库、缓存、密钥、Cookie、账号密码或影刀自动维护文件。
3. 项目专有业务参数、账号配置和其它不适合作为公共参考的信息应删除、脱敏或不收录。
4. 快照及固定提交版本保持冻结。真实项目继续开发不会自动同步到知识库。
5. 只有明确要求“更新某个真实实现参考”时，才比较案例所用提交与真实项目当前稳定提交，并选择值得参考的变化同步。

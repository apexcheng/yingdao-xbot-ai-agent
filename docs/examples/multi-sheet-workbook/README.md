# 多 Sheet 工作簿：整轮统一保存教学 Demo

这是**“整轮统一保存”这一特定策略的教学示例，不是已完成影刀实机验收的真实业务项目快照**。适用于多个业务模块共享一个 Excel / WPS 工作簿并要求最终统一保存的项目。仅演示业务组织和本地 CSV 数据处理；**不含真实 ERP 下载、XPath、凭据、钉钉 Webhook 或自动创建 Excel 文件**。

**当前多 Sheet / 多数据源 RPA 的首选真实实现参考：**[跨境补货表冻结快照](../../../reference-projects/cross-border-replenishment/README.md)。该案例展示当前确认的固定业务顺序显式调用、一个 Page 一个主函数、五个 Sheet 逐任务保存、失败恢复、妙手共享原始数据以及三国销量整体提交。不要因本 Demo 采用统一保存，就把真实项目已经确定的保存策略改回统一保存。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `run.py` | 主业务顺序、完整状态表读取、共享 `workbook`、统一保存和失败收尾 |
| `update_source.py` | 校验本轮 CSV，再更新一个专用 RAW Sheet |
| `update_country_sales.py` | 在同一个工作簿中读取刚更新的 RAW，汇总两个示例地区 |
| `config.py.example` | 脱敏路径示例；在真实项目中创建自己的 `config.py` |

真实项目使用时按已有包结构将模块放入项目根目录，并依据用户需求替换示例数据源、Sheet、日期口径和业务规则。项目应自行准备目标工作簿及来源文件，不要直接运行本目录覆盖任何生产文件。

## 示例数据契约

- 示例 CSV：UTF-8，三列表头固定为 `日期,地区,销量`，示例地区仅为 `北区` 和 `南区`，销量为非负整数。
- 已存在的工作簿包含 `订单数据`（专用 RAW 区 A:C）、`地区销量`（汇总区 A:B）和 `RPA配置区`。
- `RPA配置区!A1:E4` 依次存放：标题 `RPA更新状态`；表头 `更新对象 / 最近成功时间 / 最近尝试时间 / 最近结果 / 最近说明`；`订单数据` 与 `地区销量` 两行记录。业务行可为空，但必须保留准确的更新对象名称。
- `run.py` 通过 **一次 `get_range(1, "A", 4, "E")`** 读取标题、表头、两行五字段，转换两种时间字段，再根据业务需要读取其中的成功时间。没有为未用字段反复访问工作簿。

## 主流程与失败边界

1. 打开前检查正式文件占用，**主流程只调用一次 `xbot.excel.open(file_name=target, kind="wps")`**，直接使用正式工作簿。
2. 完整读取状态表，先准备并校验 CSV，再写入 RAW；汇总模块使用同一个 `workbook` 直接读取 RAW 值，避免依赖尚未验证的公式自动重算。
3. CSV 读取失败尚未写入业务数据：记录本数据源失败；如果当天没有可用的源数据，则汇总标记未执行。本轮其他独立来源是否继续，由真实项目的业务失败策略决定。
4. 任一业务区域写入中途失败：停止后续更新，不主动保存本轮未完成的修改，异常关闭工作簿；错误在所属业务边界通过 `raise ... from exc` 加上 Sheet 名，再由上层记录原始堆栈；不需要为日志维护 `current_step`。
5. 全部可执行阶段结束后 **统一保存一次正式工作簿**，无论本轮是否全部跳过；最后输出一次结果日志。

**适用边界：** 这是“允许数据准备失败继续 + Excel 写入失败不主动保存 + 正式文件统一保存”这一种组合。若用户明确要求每个任务独立持久化，应选逐任务保存。若汇总依赖 Excel 公式计算区，必须在真实 Office / WPS 上验证 RAW 更新后的公式结果及关闭 / 保存行为，不能把这个 Demo 当作验证证据。

代码仅使用知识库 [Excel / WPS](../../../xbot-api-docs/docs/excel.md) 正式页面已有的 `open`、`get_range`、`set_cell`、`set_range`、`clear_range`、`get_first_free_row`、`save`、`set_saved`、`close` 接口。具体 Excel 行为和项目发布流程仍需在真实影刀项目中测试。

更完整的取舍依据见 [编程风格](../../coding-style.md) 与 [多数据源安全边界](../../multi-source-report-safety.md)。

# 影刀编码版通用排错

本文用于 API 页面的局部排错仍无法解决、问题跨越数据、xbot、浏览器、Excel / WPS 或市场指令时。

## 先保留错误现场

修改代码前收集：

- 完整异常和 `traceback.format_exc()` 堆栈。
- 失败时间、当前业务步骤、必要的脱敏输入与返回值。
- 影刀版本、市场指令版本、浏览器、Excel / WPS 和 Windows 环境。
- 是否每次出现，以及能触发的最小输入。
- 第三方接口的 request id 或等价追踪标识。

不要只保留“失败了”或一张截断的截图。账号、Token、Cookie、Webhook 和客户数据必须脱敏。

## 先判断问题层级

| 层级 | 优先检查 |
|---|---|
| 业务输入 | 空值、字段名、Sheet 名、日期和文本类型、重复数据、真实文件路径 |
| xbot API | 对象来源、函数签名、参数名与类型、返回值层级、是否误用相似 Python 库 |
| 环境 | 登录状态、验证码或风控、iframe、页面结构、文件占用、Excel / WPS 进程、Windows 窗口状态 |
| 市场指令 / 接口 | 扩展版本、可视化与编码参数映射、请求体层级、限流、500 和返回结构 |
| Agent 上下文 | 是否修改了错误目录、是否读取 AGENTS、是否使用过期文档、是否把推测当成事实 |

一次只验证一个假设。先构造最小复现，再修改正式流程；不同时更换 API、数据、页面定位和异常处理。

如果排错过程中改动已经扩大成明显的结构重写或大规模重构，但问题仍未解决，优先回到原始业务结构重新做最小修改；不要继续在未经验证的大改造上叠加补丁。

## 领域检查

### 浏览器

1. URL、登录状态、验证码或异常页是否正确。
2. 元素是否位于 iframe，是否出现、可见并可点击。
3. 是否滚动了正确容器，点击后是否等待真实异步条件。
4. 元素库、XPath 或 CSS 是否仍符合当前 DOM。

见 [browser.md](../xbot-api-docs/docs/browser.md) 和 [iframe2-extension.md](../xbot-api-docs/docs/iframe2-extension.md)。

### Excel / WPS

1. 文件、工作簿、Sheet、表头行、数据起始行和列是否正确。
2. 文件是否被占用，当前驱动是否为需要的 `office`、`wps` 或 `openpyxl`。
3. 长数字是否丢失精度，以 `=` 开头的业务文本是否被当成公式。
4. 保存路径、权限和进程状态是否正常。

见 [excel.md](../xbot-api-docs/docs/excel.md)。

### 市场指令与第三方接口

1. 从 [市场指令索引](../xbot-api-docs/docs/extension-instructions.md) 进入对应正式事实页，按知识库核对公开入口和签名；报缺少模块或入口时先检查、更新或重新安装指令。
2. 对比成功与失败请求的最小差异，不根据界面中文选项猜内部枚举。
3. `HTTP 500`、`unknownError` 或空返回都是失败证据，除非当前 API 契约明确说明，不得当成“没有数据”继续破坏性写入。
4. 保留原始错误和 request id；不提交扩展内部源码、账号或令牌。

## 最小复现记录

```text
环境：影刀 / Windows / 浏览器 / Excel-WPS / 扩展版本
输入：最小脱敏数据
步骤：可重复的最少操作
实际结果：完整错误和返回值
预期结果：明确可验收
已排除：已经通过证据排除的假设
下一步：本次只验证的一个假设
```

修复后只说明实际做过的验证。语法检查、单元测试、同步影刀和影刀编辑器内运行是不同的证据等级。

# 多数据源报表安全边界

本文适用于“多个数据源或多个更新任务写入同一目标工作簿”的项目。单个 API、单个数据源或各自保存到独立文件的任务，不要机械套用。

## 先确定一致性模式

不要默认所有多数据源工作簿都必须“全成或全败”。先根据业务结果是否能够独立成立，明确采用哪一种模式。

### 强一致模式

多个数据源共同组成一个不可拆分的业务结果时：

1. 所有必需数据源都成功后，才写入新的更新时间并保存目标工作簿。
2. 任一必需数据源失败时，不提交本轮业务结果。

典型场景：多个来源共同生成同一张最终报表、同一个指标或同一批不可拆分的业务数据。

### 独立任务模式

同一工作簿内的多个 Sheet / 数据区域本身可以独立成立时，可以按任务独立提交：

1. 每个任务独立完成读取、校验、写入和成功状态提交；单个任务失败不阻塞其它无依赖任务。
2. 每个任务维护自己的最近成功时间；当天已经成功的任务是否跳过，由当前项目明确约定。
3. 存在依赖关系时，只阻塞依赖链。例如 B 依赖 A，则 A 失败只阻止 B，不应阻止无关的 C、D。
4. 失败任务不得覆盖它上一次成功时间；需要时单独记录最近尝试时间、失败原因和未执行原因。
5. 单个任务仍应保证自身写入原子性，不能因为“允许部分成功”就接受半写入结果。

这种模式适合多个数据源分别更新不同 Sheet、且业务允许“部分数据今天更新成功，部分等待修复后补跑”的场景。

无论采用哪种模式，成功或失败通知都优先在完整流程结束时统一发送，各数据模块不分别发送最终汇总通知。

## 主流程

```text
读取入口参数
→ 初始化登录或会话
→ 按已确认的一致性模式执行各任务
→ 对每个任务先读取 / 校验本轮数据
→ 按模式提交：统一提交，或逐任务原子提交
→ 关闭工作簿和页面
→ 发送一次最终通知
```

主流程应从上到下直接阅读。不为了形式统一引入巨型 `context`。

## 数据源模块

独立数据源只在代码量较多、业务边界清楚且拆出后更容易阅读时建立模块。入口只接收实际需要的页面、会话、配置或目标工作簿，不传入包含所有状态的大字典。

成功协议只选一种：

- 成功正常返回，失败抛出异常；或
- 项目已有显式布尔协议时，主流程严格检查 `is True`。

不混用“部分函数抛异常、部分函数返回 `None`、部分函数返回布尔值”的成功判断。

## Excel 写入安全

- 覆盖目标区域前，使用本轮已读取的数据确认当前业务必需的表头、列映射、数据范围和目标区域，并按已确认的业务约定判断空结果是否允许覆盖；无法确认时停止该数据源，不清空旧数据。不增加重复读取或全量预检。
- 覆盖型数据：只清空约定的数据区域，不整表 `clear()`，避免删除公式、格式和其他业务区域。
- 追加型数据：先确认最后日期或最后数据行，只追加缺失数据。
- 商品 ID、订单号、链接 ID 等长数字写入前按文本处理，避免精度丢失。
- 下载步骤必须检查返回路径非空且文件存在，不把“已点击下载”当作“文件已可用”。

## 异步导出任务绑定

网页后台常见“点击导出 → 后台生成任务 → 下载列表出现文件”的异步流程。触发导出后，不能只按“文件类型 + 今天 / 当前小时”等粗粒度条件匹配第一条记录，否则同一时间窗口内已有旧任务时，可能下载旧数据并误报成功。

推荐顺序：

1. 触发导出前，记录当前导出任务集合、任务数量或其它可稳定比较的现场信息。
2. 记录本轮触发时间，再执行导出动作。
3. 优先使用任务 ID、精确创建时间、唯一任务名等稳定标识定位本轮任务。
4. 页面没有唯一标识时，至少用“触发前快照 + 触发时间 + 新增记录”联合判断本轮新增任务。
5. 等待**这个新增任务**进入可下载状态后，再点击它的下载按钮。
6. 下载完成后继续校验本地文件确实属于本轮任务；本地文件创建时间只能作为辅助证据，不能替代网页端任务绑定。

如果无法可靠区分本轮任务与历史任务，应停止该数据源并保留旧数据，不要为了继续流程随便取第一条“看起来最新”的导出记录。

压缩包解压和解压后多文件目标识别见 [xzip.md](../xbot-api-docs/docs/xzip.md)。

Excel / WPS 具体 API 见 [excel.md](../xbot-api-docs/docs/excel.md)。

## 重试与日志

项目存在显式重试时，每次尝试开始记录尝试次数和必要业务上下文；失败时在异常处理中记录当前业务步骤及 `traceback.format_exc()` 完整堆栈。成功后停止重试；达到项目规定的最大次数仍失败时，在最后一次失败对应的 `except` 中发送一次失败通知后直接 `raise`，需要增加业务上下文时使用 `raise ... from exc`，不要把异常保存到变量后脱离原 `except` 再重新抛出，也不要静默结束。

页面打开、下载等待、验证码处理、解压、工作簿写入和最终保存等关键阶段应有可定位日志；日志服务于定位当前业务步骤，不为了“完整”给每个简单赋值和基础调用都加日志。

页面、XPath、Sheet 名、写入区域、日期口径和市场指令参数仍以当前项目为准，不从本文猜测。

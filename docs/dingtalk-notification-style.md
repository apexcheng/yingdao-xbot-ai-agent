# 钉钉通知文案与排版偏好

本页约束业务自动化项目中的钉钉通知**怎么写得清楚、像正式业务通知、方便快速处理**。API 调用方式、参数和返回值仍以 [钉钉企业机器人消息](../xbot-api-docs/docs/extensions/dingtalk-bot-message.md) 为准。

## 1. 总体风格

- 默认使用 Markdown，优先让接收人第一眼看到“发生了什么、结果怎样、是否需要处理”。
- 通知是业务结果，不写成程序日志。少写技术过程、内部状态码、变量名和无关堆栈。
- 文案简洁但信息完整。需要定位问题时，保留平台、店铺、商品 / SKU、操作时间、失败原因等最小必要上下文。
- emoji 用来做视觉分区和状态识别，不做装饰。相同含义尽量固定使用相同 emoji。
- 重要数字、结论、状态使用 `**加粗**`；普通说明不要整段加粗。
- 多条结果按“状态”分组，再按业务对象逐条展示，不把所有字段堆成一大段。

推荐的状态语义：

- `✅`：成功、完成
- `🎉`：成功数量 / 正向汇总
- `⚠️`：需要关注，但不一定是程序故障
- `❌`：失败、终态失败
- `🔁`：后续会重试 / 待重试
- `ℹ️`：说明性状态、无需立即处理
- `🚨`：程序异常或需要运维立即关注
- `🕒`：时间
- `🏪`：店铺
- `📦`：商品 / SKU 业务对象

## 2. 推荐结构

一条完整业务通知优先按以下顺序组织：

1. **标题：业务对象 + 当前结论**
2. **顶部汇总：最重要的数量 / 状态**
3. **分类明细：成功、失败、需关注项分别展示**
4. **原因 / 后续动作：只在需要时出现**
5. **分隔线 + 通知时间**

标题不要只写“通知”“执行结果”“任务完成”。优先写成：

```text
拼多多 / BOW旗舰店｜库存处理完成✅
天猫 / BOW旗舰店｜库存处理中断⚠️
库存监控阶段汇总⚠️
天猫 / BOW旗舰店｜程序异常🚨
```

## 3. 具体偏好

### 3.1 先给结论，再给过程

顶部先回答接收人最关心的问题，例如成功多少、失败多少、哪些需要人工关注。不要先写“程序于 xx 时间开始运行”“本次共扫描 xx 条消息”等过程信息。

推荐：

```text
> 🎉 补库存成功：**8 个 SKU**　❌ 最终失败：**1**
> ⚠️ ERP库存不足：**2**　ℹ️ SKU未上架：**1**
```

### 3.2 明细按状态分组

当一条通知包含多种结果时，用四级标题分组，让运营先看异常，再按需查看成功项。

```text
#### ✅ 补库存完成
#### ❌ 处理失败
#### ⚠️ ERP库存不足
#### ℹ️ SKU未上架
```

不要对每个 SKU 重复一整套“成功 / 失败 / 建议”标题。

### 3.3 单个业务对象保持固定字段顺序

同类通知中的字段顺序保持稳定，便于扫读。库存 / 商品类通知推荐：

```text
商品 → 规格 → 商品ID → 规格ID → 操作时间 → ERP映射 → 关键结果
```

示例：

```text
**1. 📦 三模蓝牙键盘**
🏷️ 规格：黑色 / 双模
🔢 商品ID：123456
🆔 规格ID：987654
🕒 操作时间：2026-09-16 18:30:21

🧩 ERP商品：K500D
🏷️ ERP规格：6927000000000｜黑色双模

📊 库存：**2 → 10**　➕ **+8**　🏭 ERP：86
```

能生成商品详情链接时，优先把**商品名称本身**做成链接，不额外增加一行裸 URL。

### 3.4 失败原因单独突出

失败、风险和人工关注原因使用引用块突出，不埋在普通字段中。

```text
> ❌ **失败原因**：库存编辑页提交后未检测到库存变化
🔁 下轮继续重试（2/3）
```

如果已经是终态：

```text
> ❌ **失败原因**：未找到对应 ERP 规格映射
🔁 已终止自动重试
```

业务通知只写接收人能理解和处理的原因。完整 traceback 留在日志；只有面向开发 / 运维且确有必要时，才额外提供技术现场。

### 3.5 @ 只用于需要人处理的通知

不要把每次成功、普通跳过或仍会自动重试的临时失败都 @ 人。

优先在这些情况 @ 对应负责人：

- 已进入终态失败，需要人工处理。
- 库存、映射、账号等业务条件不足，需要运营介入。
- 程序异常，需要运维排查。
- 待重试项长期找不到，自动流程无法自行恢复。

### 3.6 时间放在底部统一收尾

正文结束后使用分隔线，再放通知时间：

```text
---
🕒 **通知时间**：2026-09-16 18:31:05
```

阶段汇总则使用“统计区间 + 汇总时间”，不要把多个时间散落在正文顶部。
